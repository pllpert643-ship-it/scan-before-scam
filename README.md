# QRProof

QRProof คือ MVP ด้านความปลอดภัยไซเบอร์สำหรับตรวจสอบ Payment QR ก่อนจ่ายเงิน โดยอ่านข้อมูลจริงจาก Payload แทนการเชื่อเฉพาะภาพ QR

เว็บไซต์: https://pllpert643-ship-it.github.io/scan-before-scam/

## ความสามารถ

- ถอดข้อมูล QR จากรูปภาพ กล้อง การลากไฟล์ หรือการวางรูป
- วาง Payload ดิบเพื่อตรวจสอบโดยตรง
- แยกโครงสร้างข้อมูลแบบ TLV
- ตรวจ CRC16 และความสมบูรณ์ของ Payload
- อ่านผู้รับ จำนวนเงิน สกุลเงิน และเลขอ้างอิง
- เปรียบเทียบผู้รับกับ Trusted Recipient
- เปรียบเทียบยอดเงินที่ต้องการจ่ายกับยอดใน QR
- คำนวณ Risk Score พร้อมเหตุผล
- แยก Payment QR กับ URL และตรวจ URL ที่มีรูปแบบน่าสงสัย
- เปรียบเทียบ QR สองชุด
- ติดตาม QR และแจ้งเมื่อ Payload, ผู้รับ, ยอดเงิน หรือเลขอ้างอิงเปลี่ยน
- ยืนยันข้อมูลก่อนจ่ายผ่าน Confirmation Modal
- ดาวน์โหลดรายงาน คัดลอก Payload และแชร์ผลตรวจ
- Dashboard, ประวัติการตรวจ, Trusted Recipient และ Settings
- รองรับภาษาไทยและภาษาอังกฤษ โดยภาษาไทยเป็นค่าเริ่มต้น
- เก็บข้อมูลแบบ local-first ในเบราว์เซอร์ของผู้ใช้

## วิธีเดโมเร็ว

1. เปิดเว็บไซต์ QRProof
2. กด `ลองข้อมูลตัวอย่าง`
3. ใส่รหัสผู้รับที่ไว้ใจเป็น `66912345678`
4. ใส่ยอดเงินที่ต้องการจ่ายเป็น `550`
5. กด `ตรวจสอบคิวอาร์`
6. เปิด `ตรวจยืนยันก่อนจ่าย`

Payload ตัวอย่าง:

```text
00020101021229370016A000000677010111011300669123456785802TH53037645406550.0063044832
```

## เดโมกรณีเสี่ยง

### ยอดเงินไม่ตรง

ใส่ยอดเงินที่ต้องการจ่ายเป็น `600` ระบบจะแจ้งว่า QR ระบุ `550.00` และเพิ่มความเสี่ยง

### ผู้รับไม่ตรง

ใส่ Trusted Recipient เป็น `0999999999` ระบบจะแจ้งว่าปลายทางไม่ตรง

### CRC ถูกแก้ไข

เปลี่ยน CRC ท้าย Payload จาก `4832` เป็น `4833` ระบบจะแจ้งว่า CRC ไม่ถูกต้อง

### URL น่าสงสัย

วางข้อมูลนี้:

```text
https://bit.ly/qrproof-demo
```

ระบบจะแยกเป็น Web Link และแจ้งให้ตรวจสอบปลายทาง

### เปรียบเทียบ QR สองอัน

ใส่ Payload ตัวอย่างในช่องหลักและช่องเปรียบเทียบ จากนั้นเปลี่ยน `550.00` เป็น `600.00` ในชุดที่สอง ระบบจะแสดงรายการข้อมูลที่เปลี่ยน

## ความเกี่ยวข้องกับ Cybersecurity

QRProof เป็น Security Checkpoint ก่อนเข้าสู่แอปธนาคาร ช่วยลดความเสี่ยงจาก:

- QR Phishing หรือ Quishing
- การเปลี่ยนปลายทางการจ่ายเงิน
- การแก้จำนวนเงินใน Payload
- การแก้ข้อมูล QR ระหว่างการส่งต่อ
- URL ที่นำไปสู่หน้าเว็บหลอกลวง
- Social Engineering ที่เร่งให้ผู้ใช้จ่ายโดยไม่ตรวจสอบ

CRC ช่วยตรวจการเปลี่ยนแปลงของข้อมูล แต่ไม่ใช่ลายเซ็นดิจิทัลและไม่สามารถยืนยันแหล่งที่มาได้ 100% ผู้ใช้ควรตรวจชื่อผู้รับและรายละเอียดในแอปธนาคารก่อนอนุมัติทุกครั้ง

- `robots.txt` — คำสั่งสำหรับ Search Engine
- `sitemap.xml` — Sitemap ของเว็บไซต์
- `googlea1e0346ee156fc13.html` — ไฟล์ยืนยันเว็บไซต์สำหรับ Google
- `README.md` — วิธีใช้งานและรายละเอียดโครงการ

## การรันในเครื่อง

ไม่ต้องติดตั้ง Build Tool หรือ Framework เปิด `index.html` ด้วยเว็บเบราว์เซอร์ได้ทันที หรือใช้ Static Server เช่น:

```bash
python -m http.server 8080
```

จากนั้นเปิด `http://localhost:8080`

## ข้อจำกัดของ MVP

- ข้อมูลผู้รับและประวัติเก็บในอุปกรณ์นั้นผ่าน localStorage
- ยังไม่มีการเชื่อมต่อ API ธนาคาร
- ยังไม่มีฐานข้อมูลกลางหรือบัญชีผู้ใช้
- URL Detection เป็นการตรวจรูปแบบเบื้องต้น ไม่ใช่ระบบตรวจ Malware เต็มรูปแบบ
- Trusted Recipient ปลอดภัยเท่ากับข้อมูลที่ผู้ใช้ตั้งต้นไว้
- QRProof ไม่ได้โอนเงินและไม่แทนที่การยืนยันในแอปธนาคาร
